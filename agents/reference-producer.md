# Reference Producer

新 Episode 默认从这里开始。目标是复现用户指定样本的产品理解、故事推进和音画配合。
观察依据见 `docs/golden-workflow/reference-study.md`，执行合同见 `docs/golden-workflow/README.md`。
这是现有文件交接流程的总入口，复用 Source-First、事实审核和媒体生产，不新增评分角色。

新一期先读取[用户认可的 Fastlane V2 质量基准](../docs/golden-workflow/fastlane-v2-quality-baseline.md)，
查看其中的最终稿和成片；把可迁移要求交给编辑与视觉职责，完成后用实际成片对照。
自然衔接、人物需求、付费价值和结尾兑现是要求，具体段落、镜头数量和营收标题不是模板。

先找到能回答本期故事问题的来源与可用画面。Research Analyst 核验人物需求、产品动作、
付费理由和获客证据；Spine Extractor 把它们的原有关系记入 `story/story-spine.md`。
Visual Director 在写稿前检查核心操作、人物和渠道素材，将可用时间段、可见动作、
权利状态与缺口写入同一 Spine 的「可用画面」段。没有核心动作证据时，先缩小选题。

Narrative Adapter 根据同一 Spine 和素材写短片：尽快给出人物或产品与结果，随后让观众
看懂输入、操作和反馈，再解释谁愿意付钱、如何触达这些人，结尾回到具体用户价值。
第一秒的标题、画面和旁白要合起来交代具体愿望、产品用途和可见示例；不能假设观众
知道“页面”“刷新”或“下一步”指什么。
顺序服从本期证据，不必补齐所有门类。Script Editor 一次通读全文，处理连贯性、
口语和音画对应。两者始终能回看主来源，不靠多轮摘要接力。

最终稿逐段标明同期画面、Claim 与声音意图。实演连续动作可以跨句保留；命题改变时换
相应证据。强数字放上口径与日期；旁白讲人和动作，不念研究目录。Fact Guardian 同时
核对旁白与常驻标题。Visual Director 将已检查素材落实为现有 visual plan 和镜头文件。

真实 TTS 出来后，按实测语义边界配字幕、裁镜头，保持正常呼吸，不给每句补机械停顿。
原音有叙事作用时才保留，并避开旁白；音色、配乐和音效要听实际素材再判断。走现有
media → timeline → render → Delivery 检查。成片是否接近样本，需要用户对照观看；
机械校验和自行打分都不替代这个判断。

配置 `production.referenceStory` 使用 `golden-reference-v1`，采用短开场、0.12 秒默认
段尾和稳定的标题／证据／字幕版式。格式和命令见执行合同。缺失事实或素材须回到
负责角色；不得用参考视频中的台词、人物或画面替新产品补证据。
