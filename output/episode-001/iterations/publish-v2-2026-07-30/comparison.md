# Poke 发布版迭代对比

## 结论

新版相较 2026-07-30 基线存在明显、可感知的完播体验提升，达到当前素材与语音条件下
的发布标准。

## 直接对比

| 维度 | 基线版 | 发布版 |
| --- | --- | --- |
| 前三秒 | 提醒吃药、球赛、天气三项功能清单 | 一条消息发出，日历立即改动 |
| 前十秒 | 仍在解释产品从邮箱转进联系人 | 已出现“1 亿+”与“运行昂贵、很难赚钱”的冲突 |
| 全片问题 | 会不会把邮件和日历交给联系人 AI | 一个省掉界面的产品为什么会越用越贵 |
| 中段结构 | 主动提醒、授权、Recipe 依次说明 | 用户选择、产品变化、扩散动作、成本后果连续承接 |
| 数据作用 | 2 分钟后才出现一亿消息 | 开头制造悬念，后段再拆成多次后台调用 |
| 技术作用 | 解释授权和能力 | 解释一句请求为什么会持续产生推理成本 |
| 收购作用 | 后半段的信息节点 | 成本问题之后的最大故事转折 |
| 视觉节奏 | 米白背景、大标题、白卡片长期重复 | 日历动作、数字对撞、边界穿越、错误状态、调用链、公告切换 |
| 声音节奏 | 只有 TTS | 程序生成氛围底、消息提示、数字与收购节点冲击、成本脉冲 |
| 结尾 | 收购去向加一次日历错误提问 | 回答入口选择，停在少切窗口、多次后台调用与信任问题 |

## 发布依据

- Hook 真实时长 19.884 秒。
- 成片 180.544 秒，1080×1920，30 fps，H.264/AAC。
- 92 条字幕，短于 1 秒的 cue 为 0，最短 1.025 秒。
- 综合响度 -14.1 LUFS，true peak -1.0 dBFS。
- Story、Fact、Content、Delivery 门禁均通过。
- SHA-256：`672113aeb631f17c97c5d46d45d3c02d7e7003fdec669ef5298729ac81e4b523`。

## 发布边界

当前实际语音为 Microsoft Edge `zh-CN-YunjianNeural`。配置请求 MiniMax Speech，
但环境缺少 `MINIMAX_API_KEY`，因此按项目策略回退。脚本、叙事和成片技术状态已达
发布标准；更换更自然的商业中文音色仍可能提升质感，但不改变本轮故事结构结论。
