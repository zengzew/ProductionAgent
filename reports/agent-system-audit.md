# Agent 系统与成片独立审核

审核对象：`output/episode-001/vertical_9x16.mp4`（195.2s / 130 字幕 cue）、`subtitles_zh.srt`、`content/episode-001/story/`、`content/episode-001/research/`、`AGENTS.md`、`agents/`

审核结论：脚本层面是合格的产品复盘稿，但**不是一条能留住陌生观众的短视频**。核心问题不在这一版脚本，而在于整套 Agent 只审核了「文档」，从来没有人以陌生观众身份审核「成片」。

---

## 一、当前视频最严重的 5 个问题

### 1. 字幕在词中间被切断，整片看起来像机器出的残品（生产级 blocker）

`splitCaptionText`（`src/lib/captions.ts:14`）按固定 15 字硬切，不看词边界，导致：

- 英文单词被劈开：`Poke 进入 Apple M` / `essages for Bus` / `iness`（cue 77–79）
- 中文词被劈开：`人们和 Poke 交换了一亿多` / `条消息`（cue 4–5）、`邮件客户` / `端`（cue 12–13）、`对话` / `体验`（cue 20–21）、`一` / `项服务`（cue 22–23）、`越` / `用越远`（cue 28–29）、`推理成` / `本`（cue 108–109）、`开` / `发 Poke 的公司`（cue 113–114）

对短视频来说这是致命的：观众第一眼看到断词字幕，直接判定「低质自动生成」并划走。而这条链路**没有任何 Agent 负责审。**

### 2. 前三秒把陌生观众挡在门外：开场是「一家没听过的公司 + 一个没听过的产品 + 一个悬空的数字」

第一句是「Cognition 说」（cue 1，0–1.4s）。陌生观众不知道 Cognition 是谁、Poke 是什么，就被要求接受一个归因。核心数字「一亿多条消息」要到第 5 秒才出现，且被切成两段。**一个你没听过的产品的一亿条消息，对陌生人等于零信息**——它没告诉你这产品能干什么、为什么值得看。

### 3. 20 秒抛出的问题太弱：「一个邮件助手，方向为什么会变？」

这是产品经理式的问题，不是能勾住普通人的悬念。「某产品为什么转型」缺少个人利害、缺少反常识张力。观众没有理由为「一个陌生产品的方向调整」停留。真正更强的钩子（用户把邮件助手用去提醒吃药、问球赛、看天气）被放在第 40 秒，且在选题阶段被硬门槛淘汰了（见根因 5）。

### 4. 通篇是「谁说了什么」的归因脚手架 + 数据口径旁白，研究报告感很重

- `创始人说` / `创始人回忆` 在旁白里出现约 5 次，`Cognition 说`、`Poke 的条款`、`Poke 自己的页面列出了` 反复出现。AGENTS.md 明确要求来源放画面小字、旁白只点一次，但成片把出处一句句念出来。
- cue 71–73「这个口径没有拆分消息类型，也看不出同一批人会不会持续回来」——这正是 AGENTS.md 禁止的「把研究过程念给观众」。结尾 cue 127–130 再念一遍数据缺口。
- cue 82–85「模型选择、授权连接、MCP，听上去都很技术」——元评论，观众听到的是作者在自我提示，不是故事。

### 5. 中段变成日期驱动的产品编年史，且塞进了跑题的监管细节

2025年9月 → 2026年3月19日 → 六月四日 → 二零二六年初 → 六月 → 七月二十三日，一连串日期像 changelog。其中 cue 99–104（WhatsApp、欧委会、欧洲经济区、十月十五日前免费条件）是典型的「研究完整度压过理解速度」：普通观众完全不关心欧盟临时恢复条款，它打断了「产品为什么长这样」的主线。MCP（cue 84）单独蹦出来，没有一句解释它是什么。

## 二、第一处明显的划走风险

**0–5 秒。** 第一屏字幕是「Cognition 说」，接着是一串限定词（截止日 + 约三个月 + 谁交换）才到「一亿多条消息」，而这条数字又被断成两行。陌生观众在拿到任何「这产品能为我做什么」的信息之前，先被要求消化一个陌生公司名、一个陌生产品名和一个无锚点的大数字。**在他知道该不该在意之前，就被要求在意了**——这是最典型的开场流失点。

## 三、Agent 系统的根因

### 根因 A（最关键）：没有任何 Agent 审核「成片」，只审核「文档」

`critic-gate` 绑定的是 `final-script.md` 的 SHA，报告结尾白纸黑字写着「本报告不批准 script.json、音频、字幕、时间轴或视频」。`README.md` 也声明「视频制作不是这一阶段的角色」。结果：断词字幕、0.4 秒闪现的微 cue、真实 TTS 语速与停顿、首帧观感——**这些陌生观众真正看到的东西，从未经过任何以观众视角的评审。** Critic 通过的是一份读起来不错的稿子，不是一条视频。

### 根因 B：Audience Critic 的评分表奖励「信息齐全」，而不是「陌生人会不会留下」

Critic 给 Hook 打 14/15，理由是「20 秒内给出 Cognition 口径、截止日、约三个月、一亿消息、变化和问题」。这套 rubric 把「清单项到齐」当成「钩子成立」。正因如此，那个塞满限定词、把陌生人挡在门外的开场，反而拿了高分。AGENTS.md 里「陌生观众三秒内看懂」这条从未被落成一个可打分、可 blocker 的检查项。

### 根因 C：「Facts first」的逐句归因要求，和「去 AI 味」的诉求相互拉扯，没人负责收敛归因

Fact Guardian 要求每句旁白绑定 claim 并交代来源身份，这天然把脚本推向「谁说了什么」的结构。AGENTS.md 文本风格说来源进画面、旁白只点一次，但**没有任何 Agent 的门槛去强制「合并归因、删除数据口径旁白」**，于是两条规则冲突时，逐句归因赢了。

### 根因 D：去 AI 味规则是「违禁词黑名单」，抓不住本片真正的翻译腔

禁用清单命中的是「不是…而是」「破折号」「总而言之」这类显式模板。而本片真正的 AI/报告腔——归因脚手架、数据缺口旁白、日期编年、元评论——不在黑名单里，所以 Critic 的 naturalChinese 轻松给了 13/15。黑名单式规则只能防旧毛病，防不住新毛病。

### 根因 E：Hook 选题的硬门槛，把最能留人的钩子淘汰了

`hook-candidates.md` 里候选 3（用户把邮件助手用出邮箱去提醒吃药/问球赛/看天气）是最具体、最能被陌生人瞬间理解的钩子，却因为「缺少带统计周期的量化结果」被判 REJECT。硬门槛「20 秒必须出现统计口径」优先保证了事实完整度，牺牲了停留率。选中的候选 1 恰恰是最像数据发布会的那一版。

## 四、建议调整的 Agent 职责与审核门槛

### 1. 新增一个生产后评审角色：`Delivery Critic`（成片审核）

- **只读输入**：渲染出的 `vertical_9x16.mp4`、`subtitles_zh.srt`、真实 TTS 时长。
- **职责**：以陌生观众身份审「看到 / 听到的东西」，而不是脚本。
- **强制 blocker**：字幕断词/断英文单词；单条字幕 < 1.0s 的微 cue 占比过高；首帧无法被不懂产品的人理解；真实语速导致的吞字。
- **门槛**：任一 blocker 存在即 REJECT，退回生产链（captions/timeline/tts）而非退回 Script Writer。状态流在 `story-approved` 之后新增 `delivery-approved`，只有它通过才算本轮完成。

### 2. 收紧 Audience Critic 的 Hook 评分口径

- Hook 15 分里，**至少 8 分绑定「零背景可懂」**：假设观众从没听过 Poke/Cognition，第一屏是否给出「这产品能为你做什么」的具体动作，而不是一个悬空数字或陌生公司名。
- 新增硬 blocker：开场第一句以陌生公司/产品名 + 归因起头，且核心信息晚于第 3 秒，直接 REJECT。
- 信息清单「到齐」不再单独给分——齐全是前提，不是加分项。

### 3. 给 Audience Critic 增加「报告腔」硬门槛（补黑名单抓不到的部分）

- 旁白里显式来源归因（「X 说 / X 回忆 / 据 X」）超过 2 次 → 扣分并列为低分项。
- 出现数据口径/缺口旁白（「这个口径没有拆分…」「看不出…」「回答不了…」）→ blocker，来源边界只能进画面小字。
- 出现元评论（「听上去很技术」「说白了」）→ blocker。

### 4. 调整 Hook 选题门槛的优先级

- 把「20 秒必须出现统计口径」从**淘汰级硬门槛**降为**加分项**；把「陌生人 3 秒可懂的具体动作」升为硬门槛。统计口径可以在钩子之后 5–10 秒补上，不必挤进第一句。

## 五、可直接写入 AGENTS.md / agents/ 的精简规则

> 以下为建议文本，本次未改动任何项目文件。

**写入 `AGENTS.md` › Story shape（或新增 Delivery review 段）：**

- 开场第一句不得以陌生公司名或产品名 + 归因起头。第一屏必须让没听过这个产品的人知道「它能做什么」，核心信息不得晚于第 3 秒。
- 来源边界、数据口径、指标缺口只进画面小字，不进旁白。旁白不得出现「这个口径没有拆分」「看不出」「回答不了」这类对数据本身的评述。
- 显式来源归因（「X 说 / X 回忆 / 据 X」）全片旁白最多 2 次；其余出处放画面小字。
- 不写元评论（「听上去很技术」「说白了」）。技术词（如 MCP）首次出现必须紧跟一句人话解释，否则删掉。
- 中段不得写成日期编年。与用户体验无关的监管/平台条款（如欧盟临时恢复条款）不进旁白。

**写入 `agents/audience-critic.md`：**

- Hook 15 分中至少 8 分绑定「零背景可懂」：假设观众从未听过本产品，第一屏是否给出具体可用动作。信息清单齐全是前提，不加分。
- 硬拒绝新增：开场以陌生名 + 归因起头且核心信息晚于第 3 秒；旁白显式归因 > 2 次；出现数据口径/缺口旁白；出现元评论。

**新增 `agents/delivery-critic.md`（成片审核角色）：**

- 输入：`vertical_9x16.mp4`、`subtitles_zh.srt`、真实 TTS 分段时长。以陌生观众身份审看到/听到的内容，不审脚本。
- 硬 blocker：字幕在词内或英文单词内断开；单条字幕 < 1.0s 占比过高；首帧不可懂；语速导致吞字。任一命中即 REJECT，退回生产链。
- 只有 Delivery Critic 通过，本轮状态才是 `delivery-approved`；`story-approved` 不等于成片合格。

**写入 `agents/README.md` › 状态流：** 在 `story-approved` 之后追加 `→ delivery-approved`，并说明生产阶段同样有独立评审门。

**修复项（工程，非 Agent 规则）：** `src/lib/captions.ts` 的 `splitCaptionText` 需按词/词组边界切分，禁止在英文单词和中文常见双字词内部断开——这是根因 A 暴露出的具体 bug。
