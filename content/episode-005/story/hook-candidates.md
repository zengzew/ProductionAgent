# Suno Hook Candidates

## 1. 输入一句歌词，就得到一首歌（选中）

- 具体动作：输入一句歌词，几秒后得到一首带人声和伴奏的完整歌曲。
- 矛盾：听歌的人很多，做歌的人一直很少。
- 开放问题：市场后来给了它什么价？
- 硬拒绝检查：不写人人都能成音乐人的夸大，不承诺音质，不冒充真实用户个案。
- 首帧结果：第 0 帧歌词已写入输入框，生成后的歌曲波形与歌名同屏出现。
- 同期证据：持续标“功能演示”，来源小字同期出现。
- 递进台阶：三秒内歌词变歌曲，随后音乐人需求和九成创作，再问市场定价。
- 自然误解：观众可能以为是配乐工具，需要用带人声的完整歌曲纠正。

## 2. 三亿美元年化收入先落地

- 具体动作：打开 Suno，输入歌词，生成并下载成品歌曲。
- 矛盾：专业音乐制作门槛高，普通人长期被挡在门外。
- 开放问题：它靠什么收到这些钱？
- 硬拒绝检查：ARR 是公司口径，不换算利润。
- 首帧结果：第 0 帧显示 3 亿美元与公司口径同屏。
- 同期证据：数字标公司口径，来源条同期出现。
- 递进台阶：收入先落地，再切到输入歌词。
- 自然误解：零背景观众不知道这 3 亿对应什么产品动作。

## 3. 第一个用 AI 做歌的人签进了唱片公司

- 具体动作：用户用 Suno 生成歌曲，被传统唱片公司签约。
- 矛盾：AI 作品一直不被当成正式作品。
- 开放问题：AI 做出来的歌凭什么被承认？
- 硬拒绝检查：签约是个案，不写成行业趋势。
- 首帧结果：第 0 帧显示签约新闻标题。
- 同期证据：签约标新闻来源。
- 递进台阶：签约结果先落地，再回补生成动作。
- 自然误解：观众可能以为是虚拟偶像。
