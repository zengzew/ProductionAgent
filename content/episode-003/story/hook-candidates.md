# Manus Hook Candidates

## 1. 任务已经发出（选中）

- 首帧结果：任务气泡已发送，浏览器窗口已经打开并开始加载页面，完成状态从第 0 帧可见。
- 同期证据：画面持续标“功能演示”，绑定 `claim-manus-001`。
- 递进台阶：0～3 秒完成动作；3～10 秒出现八千万台虚拟电脑；10～20 秒定义云电脑，提出为什么不聊天、要自己干活。
- 自然误解：观众可能以为这只是聊天里贴了个链接，下一段用已打开的网页和云电脑纠正。
- 具体动作：发出任务后，它自己打开网页。
- 矛盾：一句任务接住真实网页操作和巨大虚拟电脑规模。
- 开放问题：为什么不聊天，要自己干活？
- 硬拒绝检查：不以产品名起头；不把演示冒充真实个案；虚拟电脑数不换算用户。

## 2. 八千万台虚拟电脑先占满画面

- 首帧结果：八千万台虚拟电脑占满画面。
- 同期证据：公司来源与“虚拟电脑，不是用户数”同时出现，绑定 `claim-manus-005`。
- 递进台阶：先给规模，再解释云电脑，最后展示打开网页。
- 自然误解：零背景观众不知道这些电脑和自己有什么关系，需要额外解释。
- 具体动作：数字从一台云电脑累积到八千万台。
- 矛盾：规模强，但第一帧缺少可感知的用户动作。
- 开放问题：这些虚拟电脑替用户做了什么？
- 硬拒绝检查：首帧过度依赖陌生数字，因此不选。

## 3. 命令先停在批准按钮上

- 首帧结果：本机终端命令停在“允许一次”按钮前。
- 同期证据：标官方桌面说明，绑定 `claim-manus-010`。
- 递进台阶：批准权 → 桌面文件 → 云电脑 → 打开网页。
- 自然误解：观众可能以为这是系统安全广告，产品价值出现太晚。
- 具体动作：手指停在批准按钮上。
- 矛盾：它能进你的电脑，却不能自己按下去。
- 开放问题：它到底要在你电脑里做什么？
- 硬拒绝检查：控制权先于产品动作，弱于选中方案。
