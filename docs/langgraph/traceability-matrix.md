## Current-test coverage boundary

The current Vitest files cover domain schemas, legacy gate bindings, workflow role order, oral checks,
story-quality helpers, captions, delivery measurements, TTS parsing and polish constraints. They do
not implement `SCHEMA-*`, `ROUTE-*`, `ARTIFACT-*`, `REVISION-*`, `REPLAY-*`, `FAILURE-*` or
`LEGACY-*` as defined by the Goal 3.0 test plan.

The current repository validators are valuable compatibility gates, but passing them cannot prove
state merge safety, deterministic routing, checkpoint recovery, HITL resume, freeze isolation,
revision convergence or event completeness.

## Exit from blocked state

After `AD-01` through `AD-16` are resolved in tracked architecture/ADR artifacts, every matrix row
must be updated with:

1. one concrete, PR-sized work-package ID;
2. its target module(s) and dependency milestone;
3. an implemented test file and command, not only a contract test ID;
4. a measurable acceptance result;
5. compatibility evidence for both Episode 001 and Episode 002 where applicable.

No row may move to `Ready` merely because prose exists. The governing schema/config and its tests must
share one versioned authority.
