## How to read this matrix

Every architecture requirement and preserved constraint maps to: its **authority**, target
**milestone + work-package ID**, target **module**, **test ID + command**, **acceptance criterion**,
**dependency**, and **current implementation status**.

- **Authority** — Goal 3.1 section and/or the governing Goal 3.0 contract.
- **WP** — work package from [implementation-plan.md §7](./implementation-plan.md#7-work-packages).
- **Test** — contract ID from [test-plan.md](../test-plan.md) and the file that will implement it under
  `tests/orchestration/`. All such files are **to implement** unless marked _existing_.
- **Command** — default `node_modules/.bin/vitest run <path>` (equivalently `pnpm test`); manual gates
  use their `pnpm validate:*` script.
- **Status** — `Existing` (already enforced) or `Ready` (unblocked, not yet built).

A `Ready` status means no architecture decision is missing; the code and its contract tests simply
have not been written.

## Current-test coverage boundary

The existing Vitest suite (10 files / 41 tests) plus `pnpm validate:*` cover domain schemas, legacy
gate bindings, workflow role order, oral-review-v2 rubric helper, story-quality, captions, delivery
measurement, TTS parsing, and polish constraints. They are retained as regression and `LEGACY-004`
compatibility evidence.

They do **not** implement `SCHEMA-*`, `RUBRIC-*` recompute, `ROUTE-*`, `ARTIFACT-*`, `REVISION-*`,
`REPLAY-*`, `FAILURE-*`, `GOLDEN-*`, or `LEGACY-001..003/005`. Passing the current suite proves the
manual pipeline is healthy; it cannot prove state-merge safety, deterministic routing, checkpoint
recovery, HITL resume, freeze isolation, revision convergence, or event completeness. Those are the
to-implement tests owned by the work packages above.

## Definition of done per row

A row moves from `Ready` to done when:

1. its work package merges with the named test file implementing its contract IDs;
2. the target module(s) exist and are exercised by that test;
3. the acceptance criterion is asserted, not merely described;
4. `pnpm test` and every `pnpm validate:*` remain green (`LEGACY-004`);
5. where applicable, compatibility is proven for both Episode 001 and Episode 002.

`WP-M2-06` additionally proves every ADR-003 eligibility condition independently and demonstrates
that `weighted_score` cannot override a protected-dimension regression.
