## 必须保持的质量

1. **开头立即看懂。** 前三秒用标题、旁白和具体画面交代产品能帮谁做什么。V2 用“给一个网址，AI帮你做宣传短视频”配候选内容，2.67秒便进入人物的推广难题；后续无需照抄句式或精确切点。
2. **讲一个人的需求和选择。** 每段接住上一段自然产生的问题。产品怎么工作、为什么值得用、第一批用户怎么来、市场给出什么回应，共同推动同一个故事；避免回到功能清单、履历和时间线罗列。
3. **文案像人在讲故事。** 使用具体动作与日常表达，减少研究报告式转接和机械自问自答。全篇读下来要连贯，不能只把每句单独改得口语化。先写来源支持的故事，再删去不推动理解的事实。
4. **讲清付费价值。** 让观众看见原来的麻烦和产品改变的工作，例如从想选题、写文案、剪视频转为挑选与调整候选。首位付费客户、使用反馈或商业结果必须有来源；缺少某类证据时换用本期可验证的回应，不补造首单或增长因果。
5. **画面随故事提供证据。** 优先可读的产品动作、人物、渠道与原文。网址框、关键按钮和证据不能被裁掉；来源、字幕各有位置。宣传动效、历史实演、编辑摘录与本次实测要分清；不用空泛流程图代替已经可取得的真实素材。
6. **结尾有回报。** 回到开头的人物、需求或用户变化，让重新出现的产品画面有新的意义；不重复按钮步骤，不用空泛总结或强行关注口号收尾。
7. **按真实声音剪片。** 40–80秒，目标60秒；用真实TTS与最终MP4读回调整字幕和切点。检查吞字、停顿、字幕同步、界面可读性和黑屏，不用空白或拉长静帧凑时长。

## 在现有流程中执行

Reference Producer 开始新一期时先读本基准，并查看基准最终稿与成片。Narrative Adapter 和 Script Editor 在现有编辑记录中指出本期最关键的衔接、价值解释与结尾如何实现这些要求；若仍像说明书，先改稿再生成配音。Visual Director 按实际素材确认可读动作，不能只照搬版式。

Delivery Critic 对照的是新一期真实成片与本基准，记录具体时间点的不足，交回现有责任角色修正后再渲染。用户已认可本基准，无须每期重新申请使用；每期事实、素材、TTS和Delivery仍独立检查，不继承这期的PASS。没有看过成片或听过音轨的项目如实保留未知，不用评分和测试全绿替代。

本次用户反馈确认整体创意质量可作为后续标准；此前报告中的完整人工听感待核验记录不被追溯改写。用户没有逐项声明耳机听辨、发布许可或真实留存数据。本基准因此不是播放量保证，也不要求固定音色、固定镜头数、固定收入标题或一模一样的段落结构。

## 后续反馈的应用边界

[Episode-010 人工反馈复盘](episode-010-feedback-learning.md)补充了本基准的执行判断：连续检查相邻段的真实声音，识别无语义动机的突然赶词，并按想法的收束与转换安排呼吸。固定TTS速度、平均字速和默认段尾不能证明自然；允许服务表达的快慢变化，不把每句拉成等速或等长停顿。此处解释既有第3、7条，不新增数字门槛。

封面可以借鉴参考的层级与表达机制，但要围绕本产品重新组织主体和场景。电脑能说明本期办公场景，不是后续必备道具；强态度标题是可选包装，其承诺仍须由具体内容兑现。用户对本期标题的偏好与编辑避免泛称的原则存在张力，详见复盘，不强行消除。认可一个案例不要求复制其叙事结构、配色或视觉语言。
