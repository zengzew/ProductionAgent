## Episode 001

### v1 摘要

v1 已经用“一句话改好日历”作为开场，并解释联系人入口、Beta 用户请求和 Recipe。后段又进入一亿消息、后台持续运行成本和 Cognition 收购现状，最后再次复述一亿消息。产品信息完整，但核心问题在后半段被成本和公司现状分散。

### v2 摘要

v2 第一帧直接显示周三会议改到 15:00，十秒内说明 Poke 是联系人列表里的 AI，并把悬念落到用户还愿意交出哪些日常任务。故事只保留旧流程麻烦、团队收起工作台、内测用户扩展用途、授权动作和 Recipe 分享；开放节点只用一句交代当前使用状态，最后回到同一张日历。

### 主要变化与预期改善

- Hook 顺序从“动作 → 规模 → 产品定义”改为“动作 → 产品定义 → 规模与问题”，降低零背景理解成本。
- 删除运行成本、收购现状和重复规模数字，成片比 v1 缩短 26.432 秒；真实 TTS Hook 在 19.980 秒结束。
- 一亿消息只作为规模背景，不再让旁白念“消息数不是用户数”等研究边界。
- Recipe 与官方 Release Notes 同期出现；所有合成操作明确标注“功能演示”。
- 口播复审将“Beta 用户”“一般可用状态”和含混转折改成日常中文；Audience Critic 最终以 90 分 PASS。

详细对比见 `content/episode-001/v2-goal3/production/comparison-report.md`。

## Episode 002

### v1 摘要

v1 已有“三天后才到”的强开场，也覆盖慢速送达、路线、训练、用户故事、增长、商店和位置权限。后段加入终身支持档销量、融资状态和“慢速社交赛道信号”，旁白接近研究报告；画面模板还包含来源没有支持的剩余时间、具体鸟种速度和价格信息。

### v2 摘要

v2 仍从已经出发、三天后才到的消息开场，但前二十秒加入“用伊丽莎白时代英语等鸟送信”的具体用户行为。中段先解释等待为什么有价值，再讲朋友推动公开、路线如何可见、用户怎样玩出通信仪式；后段只保留支持方式和距离所需的权限边界，最后回到同一只鸟。

### 主要变化与预期改善

- 把可复述的人类行为提前到 Hook，核心问题从抽象的“慢为什么让人期待”变成“等待为什么值得讲给别人”。
- 删除融资、终身档销量和赛道判断，成片比 v1 缩短 26.300 秒；真实 TTS Hook 在 19.356 秒结束。
- 研究时间线把不精确的“古英语”改回来源支持的“伊丽莎白时代英语”。
- 最终画面移除无 Claim 支持的剩余时间、具体鸟种速度、价格、结尾 10 万数字和“市场信号”。
- 用户、活跃对话、注册用户和零付费获客保持分口径展示，不互相换算；“独立体验者”和“在那篇体验里”已改成自然回指，且始终限定为同一名作者。

详细对比见 `content/episode-002/v2-goal3/production/comparison-report.md`。

## 已知风险

- 两版没有真实受众 A/B 数据，54/60 只代表当前编辑代理评分。
- MiniMax 凭据缺失，本轮按配置回退到 `zh-CN-YunjianNeural`；TTS provider 与目标默认配置不同。
- 成片已经做编码、峰值、静音区间、字幕、时长和视觉抽帧检查，但没有耳机环境下的人工听感盲测。
- Episode 001 的 10～20 秒仍同时包含规模、早期形态和问题；Episode 002 的 90～124 秒仍是数据、商店与权限连续出现的最高密度区。
- 为兼容当前只接受扁平 episode ID 的生产脚本，仓库增加了指向嵌套 v2 目录的别名链接；物理产物仍全部保存在要求的 `v2-goal3/` 文件夹内。

## 人工评审清单

建议连续观看 v1 与 v2，不先读脚本。每集分别记录：

- [ ] 第一帧是否不依赖产品背景也能看懂已经发生什么？
- [ ] 20 秒结束时，能否复述产品是什么、正在等哪个答案？
- [ ] 第一次想划走的时间点在哪里？原因是重复、说明感、来源负担还是画面不可读？
- [ ] 每 20～40 秒是否出现新的用户动作、产品选择、证据或判断变化？
- [ ] 能否用一句话复述本集最值得转述的发现？
- [ ] 真实页面、来源标签和“功能演示”在手机尺寸下是否可读？
- [ ] 字幕是否遮挡证据，是否有词组或英文单词被拆开？
- [ ] 旁白是否自然，有没有吞字、停顿不顺或回退音色不适配？
- [ ] 结尾是否兑现开场，没有突然转成功能总结、赛道判断或互动 CTA？
- [ ] v2 是否在少讲内容的同时，让产品价值更清楚？
